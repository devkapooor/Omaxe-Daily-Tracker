## Isolation and loading design observed

Separate root firebase.drill.json and tests/drill/vite.config.ts use demo-alphahub-drill, local Auth9099, Firestore8080 and Functions5001. Real src/main.tsx/app/profile gates and unmodified Rules/Functions are used. Browser HTTP routing and Node socket guards deny nonlocal business traffic. SDK identity is checked before sign-in; actual Auth/Firestore/Functions traffic and saved local records establish isolation. No production env file is overwritten or loaded by the drill Vite config. The production posSandboxes/test path is never treated as a disposable database.

Current Stock blank+All is idle; barcode matching is exact and keeps leading zeros; server cursor pages50 and cost-ID batches≤30. MRP/cost/margin sorts are labelled page-only. Details subscribe to product+cost only while open; recorded history is lazy. Stock History merges existing movement/damaged sources with25-row streams, an as-of boundary, stable IDs, honest missing fields and labelled damaged-return product-filter limitations. Source details are fetched on opening. POS daily totals use bounded100-row realtime pages until the selected day is complete, plus state-ID chunks. Hidden POS/Stock tabs unmount their dependencies; truly shared counter/global dependencies remain.

Firestore cannot provide arbitrary substring catalogue search or derived global margin sorts without another indexed/read-model approach. Page-only sort and exact barcode are the approved current behavior. Combined history needs per-source cursors and stable merge/de-duplication; emulator queries do not certify production composite-index readiness. Global financial/users/vendor/cashout/transfer collections still have broad subscriptions, and server holder calculations inspect broad records. These are scaling concerns, not measured production read savings. Current Rules/indexes are preserved.
